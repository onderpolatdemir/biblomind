This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

BiblioMind is an AI-powered book discovery and e-commerce platform. Users can photograph their bookshelf and receive personalized book recommendations. The system combines computer vision (Google Cloud Vision), semantic search (pgvector + Elasticsearch), and a RAG-based chatbot (LangChain + GPT-4o).

## Architecture

```
biblomind/
├── backend/          # FastAPI (Python 3.11+)
├── frontend/         # Next.js 14 (App Router, TypeScript)
├── docker/           # Docker configs
└── docker-compose.yml  # PostgreSQL (pgvector), Redis, Elasticsearch
```

**Infrastructure (all via Docker):**
- PostgreSQL 16 + pgvector — exposed on port **5440** (not 5432)
- Redis 7 — port 6379
- Elasticsearch 8.11 — port 9200, security disabled

## Backend

### Setup & Running

All backend commands must be run from the `backend/` directory.

```bash
# 1. Start Docker infrastructure
docker-compose up -d  # run from project root

# 2. Start backend server (Git Bash / Linux)
cd backend
./scripts/utils/start_server.sh

# Windows PowerShell
.\scripts\utils\start_server.ps1

# Or manually:
cd backend
source venv/Scripts/activate   # Windows Git Bash
# venv/bin/activate on Linux/Mac
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

The start script sets `DATABASE_URL=postgresql://postgres:postgres@localhost:5440/bibliomind` automatically.

### Key URLs

- Swagger UI: http://localhost:8000/docs
- Health: http://localhost:8000/api/health

## Backend Code Architecture

### Layer Structure
```
app/
├── api/          # FastAPI route handlers — thin, delegate to services
├── services/     # All business logic lives here
├── models/       # SQLAlchemy ORM models
├── schemas/      # Pydantic request/response schemas
└── core/         # Config, DB session, middleware, caching, rate limiting
```

### Auth Pattern
`app/api/deps.py` provides three FastAPI dependencies:
- `get_db` — yields a SQLAlchemy session (always close on teardown)
- `get_current_user` — decodes JWT Bearer token → User model
- `get_current_admin_user` — same but asserts `user.is_admin`

JWT tokens use HS256. Token type (`"access"` vs `"refresh"`) is stored in the payload and validated on every request.

### AI / Vector Search

**Book embeddings:** Each `Book` has an `embedding` column (`Vector(1536)`), generated by `text-embedding-3-large`. Used for cosine similarity queries via pgvector.

**User preference vector:** `User.preferences_vector` (`Vector(1536)`) — a weighted average of the embeddings of books the user has interacted with. Weights by interaction type: `purchase=1.0`, `like=0.8`, `cart=0.5`, `view=0.2`. Updated by `RecommendationService.update_user_preference_vector()`.

**Recommendation scoring (hybrid default):**
```
final_score = 0.70 * content_similarity + 0.20 * popularity + 0.10 * recency
```
Favorite author match adds +0.4 to content score; favorite genre match adds +0.15.

**RAG Chatbot pipeline** (`app/services/rag_service.py`, `chat_service.py`):
1. Fuzzy-match user message against book titles (threshold 0.70, uses `fuzzywuzzy`)
2. If books detected → `book_detection` strategy (retrieve exact books from DB)
3. Otherwise → `recommendation_engine` / `popular_books` / `no_books` strategy
4. Build context string → GPT-4o for final answer
5. Conversations capped at 5 per user; auto-title generated by GPT-4o

**Vision pipeline** (`app/services/vision_service.py`):
- Google Cloud Vision OCR with 4-direction rotation fallback
- Detected text fuzzy-matched against DB books
- Returns matched books with compatibility scores

### Caching

`app/core/cache.py` provides a `@cache_result(prefix, ttl)` decorator that uses Redis DB 1. The OpenAI service uses Redis DB 0 for token tracking. Cache is silently disabled if Redis is unreachable.

### Rate Limiting

`slowapi` integration in `app/core/rate_limit.py`. Vision API is rate-limited separately (`VISION_API_RATE_LIMIT_PER_DAY`).

### API Router Registration

All routers are registered in `app/api/__init__.py` under the `/api` prefix. Adding a new domain requires: model → schema → service → api module → register in `__init__.py`.

## Frontend

### Setup & Running

```bash
cd frontend
npm install
npm run dev    # http://localhost:3000
npm run build
npm run lint
```

### Architecture

Next.js 14 App Router. Pages in `src/app/`, shared components in `src/components/`.

**Global Providers** (set up in `src/app/layout.tsx` wrapping order):
```
AuthProvider → FavoritesProvider → CartProvider → {children} + ChatWidget
```
`ChatWidget` is rendered globally so the chat persists across page navigation.

**Auth flow** (`src/context/AuthContext.tsx`):
- JWT stored in `localStorage` under the key `"token"`
- On mount, calls `GET /api/auth/me` to verify token and hydrate user state
- Public paths: `/`, `/auth/login`, `/auth/register` — everything else requires auth
- 401 response in `src/lib/api.ts` interceptor removes the token and redirects to `/auth/login`

**API client** (`src/lib/api.ts`): Axios instance with base URL `http://localhost:3000/api` (via Next.js rewrites or direct to port 8000). Bearer token injected from localStorage on every request.

**State management:** React Context for auth, cart, and favorites. No Redux/Zustand at the page level.

## Important Constraints

- The PostgreSQL container uses port **5440**, not the default 5432. Connection strings must use `@localhost:5440`.
- Scripts in `backend/scripts/dangerous/` (e.g., `clear_books.py`) delete data — never run without intent.
- All backend scripts must be run from the `backend/` directory (not the project root), because `app.core.config` resolves `.env` relative to the package location.
- The `backend/venv` is the active virtualenv for server runs. `backend/scripts/venv` is a separate env used only by isolated scripts.
- Elasticsearch index name is `books` (configurable via `ELASTICSEARCH_INDEX`). The ES container has security (`xpack.security`) disabled.
