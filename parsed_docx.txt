BiblioMind is an "AI-Powered Book Discovery Platform" designed to bring the personalized experience of the digital world to physical libraries and bookstores. Unlike traditional e-commerce sites, BiblioMind focuses not only on the user's purchase history but also on instant visual inputs and deep literary preferences. 
The most crucial feature of the project is enabling the user to photograph someone else's bookshelf and discover the works best suited to them from that collection via artificial intelligence.
The system architecture utilizes FastAPI for high-performance asynchronous backend processing and Next.js for a responsive frontend interface. The core functionality relies on Google Cloud Vision API for Optical Character Recognition (OCR) to extract book titles from images. These titles are then matched against a vector database (PostgreSQL + pgvector) containing semantic summaries of books. Finally, a Large Language Model (LLM) generates personalized, empathic explanations for each recommendation, constituting the "Why Module".
This report details the progress made during the first phase of development, including the establishment of the database schema, the integration of the Vision API, and the implementation of the core recommendation algorithms. The initial results demonstrate the system's ability to successfully digitize a physical shelf and retrieve semantically relevant book suggestions.
KEYWORDS: Artificial Intelligence, Book Discovery, Computer Vision, Recommendation Systems, OCR, NLP, Vector Database.

1. INTRODUCTION
1.1 Background
The digital transformation of the book industry has created new opportunities for readers to discover and purchase books online. However, existing recommendation systems often rely on explicit user preferences or purchase history, which may not accurately reflect a user's reading interests. Additionally, many readers maintain physical book collections that are not integrated into digital discovery platforms.
BiblioMind addresses these limitations by introducing a novel approach to book discovery that combines computer vision, semantic understanding, and personalized recommendation algorithms. The platform allows users to photograph their existing book collections and receive intelligent recommendations based on the semantic similarity between their current books and potential new reads.
1.2 Problem Statement
Traditional book recommendation systems face several challenges:
1. Limited Context Understanding: Most systems rely on explicit ratings or purchase history, which may not capture the nuanced preferences of readers.
2. Disconnect Between Physical and Digital: Readers with physical book collections cannot easily leverage their existing books for digital discovery.
3. Generic Recommendations: Many platforms provide generic recommendations that do not account for the specific reading patterns and preferences of individual users.
4. Inefficient Discovery Process: Users often spend significant time browsing through irrelevant suggestions before finding books that match their interests.
1.3 Objectives
The primary objectives of the BiblioMind project are:
1. Photo-Based Recognition: Develop a robust system that can identify books from photographs of bookshelves using OCR and computer vision techniques.
2. Semantic Understanding: Implement a recommendation engine that understands the semantic content of books and user preferences using vector embeddings.
3. Personalized Recommendations: Create a personalized recommendation system that suggests books based on semantic similarity to a user's existing collection.
4. E-Commerce Integration: Provide a seamless e-commerce experience that allows users to purchase recommended books directly through the platform.
5. Scalable Architecture: Design and implement a scalable system architecture that can handle growing user bases and book catalogs.
1.4 Scope
This project encompasses:
- Backend API development using FastAPI
- Frontend development using Next.js 14
- Database design and implementation with PostgreSQL and pgvector
- Integration with Google Cloud Vision API for image processing
- Integration with OpenAI API for embeddings and text generation
- Implementation of vector similarity search algorithms
- Development of user authentication and authorization systems
- E-commerce functionality including cart management and order processing
- Deployment infrastructure using Docker and cloud services
1.5 Significance
BiblioMind represents a significant advancement in book discovery technology by:
- Bridging the gap between physical and digital book collections
- Leveraging state-of-the-art AI technologies for personalized recommendations
- Demonstrating practical applications of vector databases in recommendation systems
- Providing a user-friendly interface for book discovery and purchase

3. MATERIAL AND METHOD
This section details the engineering resources, software architecture, and procedural methodologies applied to realize the BiblioMind platform. While Section 2 established the theoretical foundations of the similarity algorithms, this section focuses on the practical implementation, data pipelines, and integration strategies.
3.1. Materials
The material basis of the project consists of the technology stack selected for high-performance AI processing and the datasets curated for the recommendation engine.
3.1.1. Technology Stack
The system is built upon a microservices architecture utilizing the following core components:
Backend Engine: FastAPI (Python) was selected as the primary web framework due to its native support for asynchronous I/O operations. This is critical for managing concurrent requests to external AI services (OpenAI and Google Cloud) without blocking the main thread, ensuring high throughput.
Database Systems:
PostgreSQL with pgvector: Serves as the persistent storage for user data and book metadata. The pgvector extension is instrumental for storing 1536-dimensional embedding vectors and performing nearest neighbor searches.
Elasticsearch: Deployed to handle fuzzy string matching and keyword-based search queries, providing resilience against OCR errors (e.g., misspelling "Orwell" as "0rwell").
Redis: Utilized as an in-memory data structure store to cache frequent queries and manage user sessions, reducing latency.
Frontend Interface: Next.js (React) is employed to provide a server-side rendered (SSR) interface, optimizing the application for search engine visibility and initial load performance.
AI Services:
Google Cloud Vision API: Used for text detection (OCR) and object segmentation within images.
OpenAI API: Provides the text-embedding-3-large model for vectorization and gpt-4o for generating natural language explanations.
3.1.2. Data Collection and Preparation
To establish a functional MVP, a dataset of approximately 10,000 books was aggregated from open-source repositories (Goodreads and Open Library). The raw data underwent a cleaning process to normalize author names and remove incomplete entries.
3.2. Methodology
The development methodology follows a pipeline approach, processing raw inputs (images or text) through distinct stages to generate the final recommendation.
3.2.1. Vectorization Pipeline
Before the system can recommend books, the text data must be converted into a machine-understandable format.
Summarization: Book descriptions are concatenated with metadata (Title, Author, Genre).
Embedding Generation: This combined text is passed through the embedding model to generate a high-dimensional vector.
Indexing: These vectors are stored in PostgreSQL using an IVFFlat (Inverted File with Flat Compression) index. This indexing method allows for approximate nearest neighbor search, which significantly speeds up the retrieval process described in the theoretical framework.
3.2.2. Visual Data Processing (The Vision Pipeline)
A specific challenge identified in the requirements was the recognition of book spines, which are often thin, curved, or feature vertical text. To address this, a pre-processing method was implemented:
Image Pre-processing: Uploaded images are analyzed using OpenCV. If the text density confidence is low, the image is automatically rotated by 90 degrees to assist the OCR engine in recognizing vertical text.
OCR and Filtering: The Google Cloud Vision API returns a raw stream of text. A regular expression (Regex) filter is applied to discard non-title text (e.g., publisher logos, volume numbers) and isolate potential book titles.
3.2.3. Semantic Search Implementation
The core recommendation logic implements the mathematical principles defined in Section 2.2.
Instead of recalculating the cosine similarity for every book in the database (which would be computationally expensive), the system queries the pgvector index.
The query execution plan utilizes the <=> (cosine distance) operator provided by the extension to efficiently retrieve the top-$k$ results that satisfy the maximization criteria of the Ranking Optimality theorem.
3.2.4. RAG (Retrieval-Augmented Generation) Workflow
The final stage employs a RAG architecture to provide context to the Large Language Model.
Context Retrieval: The system retrieves the metadata of the selected top-5 books.
Prompt Engineering: A dynamic prompt is constructed, injecting the User's Preference Profile and the selected Book's Metadata.
Generation: The LLM is instructed to act as a "literary curator," explaining the connection between the user's known preferences (e.g., "dystopian themes") and the recommended book, resulting in a personalized output.

4. RESULTS
The development of the BiblioMind platform has progressed from the architectural design phase to the active implementation phase. During this interim period, the core infrastructure has been established, and the primary AI pipelines have been successfully prototyped. The key technical results achieved so far are summarized below:
4.1. Infrastructure and Backend Implementation The microservices architecture has been successfully deployed using Docker containers. The FastAPI backend is fully operational, handling asynchronous requests for the application. A robust authentication system using JWT (JSON Web Tokens) has been implemented, securing the API endpoints for user registration and login. The Next.js frontend environment has been configured, and the basic authentication pages are functional.
4.2. Database and Vector Search The PostgreSQL database schema has been finalized and deployed. The pgvector extension was successfully enabled to support high-dimensional vector operations.
Data Ingestion: A dataset of approximately 10,000 books was cleaned and imported into the system.
Embedding Generation: Using OpenAI's text-embedding-3-large model, semantic vector embeddings (1536 dimensions) were generated for all books in the dataset.
Search Performance: Preliminary tests of the vector similarity search (using IVFFlat indexing) demonstrated that the system can retrieve semantically relevant books in under 200ms, validating the feasibility of the recommendation engine.
4.3. Vision Pipeline Prototype The integration with Google Cloud Vision API has been established. A dedicated endpoint (/api/vision/analyze) was created to accept image uploads.
OCR Results: Initial tests show that the system can successfully extract raw text from high-quality images of bookshelves.
Challenges: As anticipated, the Optical Character Recognition (OCR) accuracy drops when book spines feature vertical text or low contrast. To mitigate this, the pre-processing module described in the methodology (image rotation and contrast enhancement) is currently being integrated.
4.4. Recommendation Logic The "Vision-to-Recommendation" algorithm has been coded and unit-tested. The backend logic that takes a list of detected book titles, converts them to vectors, and calculates the Cosine Similarity against the user's preference profile is functional. The system is now capable of ranking books based on mathematical proximity to the user's interests, ready for the final frontend integration.
5. CONCLUSIONS
The interim development of the BiblioMind project has successfully demonstrated the feasibility of bridging the gap between physical book discovery and digital personalization through Artificial Intelligence. This study has moved beyond the conceptualization phase to establish a robust technical infrastructure, validating the core hypothesis: that visual inputs from the physical world can be effectively translated into semantic queries to drive personalized recommendations.
Contributions to Basic and Applied Aspects
From a theoretical perspective, this project contributes to the field of Information Retrieval (IR) and Recommender Systems by implementing a Vector Space Model (VSM) in a novel context. While traditional recommendation systems rely heavily on collaborative filtering (user-item interaction matrices), BiblioMind emphasizes content-based filtering enhanced by Deep Learning embeddings. By representing both the user's complex literary preferences and the semantic content of books as high-dimensional vectors in the same latent space, the system overcomes the "cold start" problem often found in collaborative systems. The project demonstrates that semantic similarity, calculated via cosine distance, offers a superior metric for determining relevance compared to keyword-based matching, especially when dealing with the nuanced themes of literature.
On the applied engineering aspect, the project presents a scalable Microservices Architecture that orchestrates distinct AI domains—Computer Vision and Natural Language Processing (NLP)—into a cohesive workflow. The successful integration of Google Cloud Vision API for extracting text from unstructured images of bookshelves , followed by the immediate mapping of this text to a local PostgreSQL database extended with pgvector, serves as a practical blueprint for "Real-World-to-Digital" applications. Furthermore, the implementation of the Retrieval-Augmented Generation (RAG) pipeline contributes to the field of Human-Computer Interaction (HCI) by shifting the user interface from static lists to dynamic, empathic, and "human-like" explanations generated by Large Language Models (LLMs).
Findings and Suggestions
The experimental results obtained during the first two phases of development have yielded several critical findings that shape the future direction of the project:
OCR Sensitivity and Pre-processing: The initial tests revealed that standard Optical Character Recognition (OCR) engines struggle with vertically oriented text, which is common on book spines. It was observed that the accuracy of text extraction drops significantly when the image is not aligned. Based on this finding, it is suggested and planned to implement a rigorous image pre-processing layer using OpenCV. This layer will perform automated 90-degree rotations and contrast enhancement before the image is sent to the Cloud Vision API, ensuring higher fidelity in text detection.
Latency and Optimization: While vector similarity searches are computationally efficient (under 200ms), the round-trip latency for external API calls (Vision and OpenAI) creates a bottleneck. To address this applied constraint, it is suggested to implement aggressive caching strategies using Redis. Common search queries and previously analyzed images should be cached to reduce dependencies on external services and improve response times for the end-user.
Semantic Nuance: The use of embeddings has proven successful in capturing genre and tone (e.g., "dystopian," "melancholic"). However, to further refine the "Empathic Recommendation Engine," the system requires a feedback loop. Future work should suggest incorporating an explicit user feedback mechanism (e.g., "Why did you like this recommendation?") to fine-tune the user preference vectors dynamically over time.
In conclusion, the BiblioMind project has established a solid technical foundation. The remaining development phases will focus on optimizing the "Vision-to-Recommendation" pipeline, implementing the "Book Buddy" social layer, and finalizing the user interface. The study confirms that combining visual data processing with semantic AI offers a transformative approach to how users interact with physical book collections.
